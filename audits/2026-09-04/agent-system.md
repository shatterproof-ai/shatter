## 2. Contradictions

1. **Grep/Read tools vs Bash.** AGENTS.md: "Use Grep/Glob/Read tools, not shell grep/cat/sed". Auto-mode harness prompt and the RTK block in the same AGENTS.md: "do your work through Bash / always prefix with rtk". Global memory: rtk corrupts file redirects and serves stale refs, and the Bash tool's `grep` is a ugrep shell function. Three incompatible instructions about the same action.
2. **Subagent strategy.** Global `codex/AGENTS.md`: "use subagents liberally… offload to subagents". Memory `feedback_agent_teams`: "Do NOT use background subagents — TeamCreate with visible tmux panes". AGENTS.md: "Spawn teammates in the foreground". CLAUDE.md "Subagent priming" section assumes plain subagents.
3. **Skill-first vs hard triggers.** superpowers: "invoke a skill before ANY response, brainstorming before plan mode". bento: `launch-work`/`land-work`/`cross-check`/`issue-readiness-check` are "hard triggers". Global AGENTS.md: "use the Bento workflow skills rather than restating the procedure inline". Nobody says which wins when e.g. `superpowers:using-git-worktrees` and `bento:launch-work` both claim the worktree step.
4. **Never edit on main vs `/audit`.** The audit skill ends with "commit `audits/YYYY-MM-DD.md` with message `audit: …`" and creates issues, but the require-worktree hook blocks the Write on main and the global rule forbids presenting main as an option. Result in practice: the 2026-07-10 audit (str-sff87, still `in_progress`) has **no committed report** — only the memory file says "Authoritative report: audits/2026-07-10.md", which does not exist.
5. **Landing procedure ×3.** AGENTS.md "Landing the Plane" (manual rebase/merge/push in primary checkout), `bento:land-work` (lease + preview worktree + verifier), and `superpowers:finishing-a-development-branch`. The memory file `feedback_primary_checkout_diverged_local_main` documents a fourth, improvised path (commit the merge inside the preview). The dotfiles SCM guidance ("explicit merge commit, no ff") is consistent with all, but AGENTS.md still says `git push --force-with-lease` and `git checkout main`, both of which the hook/worktree model and bare primary make wrong.
6. **Verifier vs CI.** `scripts/land_work_verifier.sh` comments "runs the same gates ci.yml uses" but runs `test-standard + parity + conformance`; CI runs `task check` (+ shatter-llm separately). `/pre-completion` runs `task affected`. Three different definitions of "verified".
7. **Worktree cleanup.** AGENTS.md: "Never run `git worktree remove` yourself — Claude Code prompts at session end" (only true for `--worktree` sessions) vs bento `land-work`: "tear down the feature branch and its linked worktree afterward". Combined with `check-unpushed` Stop hook, agents leave worktrees rather than risk either rule — see 8 lingering worktrees.
8. **Hook bypass.** Memory `project_beads_git_hook_timeout` and `project_shatter_git_hook_test_corrupts_worktree` tell agents to use `core.hooksPath=/dev/null` and `--no-verify`; AGENTS.md says "Leave the managed git hooks alone… never in a way that persists"; memory `feedback_verify_hooks_before_bypass` says don't bypass by analogy. The corrupting-test bug is recorded as fixed (2026-07-05) but the `--no-verify` advice was never retracted.
9. **Model/permissions.** Global settings: `"model": "sonnet"`, `defaultMode: auto`, `skipDangerousModePermissionPrompt`, and a global allowlist including `git checkout/reset/merge/rebase/clean`. `.agent-mode.local` = `dangerous`. Meanwhile the docs invest heavily in "never edit main" prose — the guardrail is one hook, everything else is trust.
10. **Dotfiles chain.** `codex/AGENTS.md` says "Follow the shared repo-root instructions in `~/dotfiles/AGENTS.md`", which is the dotfiles *project* doc (install.sh, sandblaster, tmc). Its "Answering Why Questions" and RTK sections are the only globally relevant parts.

## 4. Recommendations (issue-ready)

### Shatter repo

1. **Repair and guard the primary checkout (`core.bare=true`).** `.git/config` has `bare = true`, so `git status`/`checkout` fail in `/home/ketan/project/shatter` and every landing instruction that touches the primary checkout is broken. Unset it, then add a check to `scripts/setup-hooks.sh --check` (and/or a drift-patrol check) that fails on `core.bare=true`, `core.hooksPath` overrides, and prunable worktrees so the state cannot silently persist.
2. **Add a `task check --fresh` (or `scripts/gate-wrapper.sh --no-cache`) that clears `.task/checksum` for the selected stages, and make `land_work_verifier.sh`, CI and `/pre-completion` use it.** Today 19 leaf tasks are checksum-cached and `--force` doesn't propagate through `check-governed`, so every "PASS" from `task check`/`task affected`/the verifier can be a no-op. Document the caching semantics in CLAUDE.md's test-tier table and have the verifier emit the list of tasks that actually executed (Task's `--verbose`/`-v` "task is up to date" lines) so a zero-execution pass is visible.
3. **Make `scripts/land_work_verifier.sh` match CI or say it doesn't.** Its header claims "same gates ci.yml uses" but it runs `test-standard+parity+conformance` while CI runs `task check` (+`shatter-llm`). Either run `task check` (one heavyweight slot) or rename the claim and add `"timeout"` to `verifier.json`; also tee raw verifier output to a file so a killed first run leaves diagnosable evidence instead of the "retry once" folklore in memory.
4. **Rewrite `/audit` to be worktree- and tracker-safe.** Change Phase 10 to: create a beads audit issue first, run `bento:launch-work`, write `audits/<date>.md` in that worktree, file findings as children of the audit issue with `--parent`, and land via `land-work`. Add a drift-patrol `tracker-hygiene` sub-check: an `audit`-typed issue in_progress >14 days or an audit issue whose report file is missing fails. Close or finish `str-sff87` (report never committed).
5. **Cut AGENTS.md by ~40% and delegate to bento.** Remove "Landing the Plane" manual git sequence (contradicts land-work and is impossible on a bare primary), the RTK block (already global), the manual swarm procedure, and "never run `git worktree remove`" (true only for `--worktree` sessions). Keep: bd quick ref, issue shape/sizing, parity rules, resource etiquette, beads sync cadence. Run `bento:compress-docs` and pin a byte budget test (`scripts/test_agent_docs_budget.py`) so growth is caught.
6. **Split per-crate CLAUDE.md files (54K/32K/22K) into a short rules file + linked reference docs.** They are injected wholesale on first Read; a Go+TS task costs ~22k tokens of prose. Move issue-by-issue history (`str-nm5e`, `str-b66s`…) to `docs/<frontend>/`, keep the parity contract and ≤2K of rules. Add a test asserting the per-crate parity tables equal `protocol/parity-matrix.yaml` (generate them from it) so the matrix is the only hand-edited source.
7. **Land `str-u394l.4` (agent-rules drift lint).** A `task meta` check that every backticked `task <name>` / `scripts/<file>` / `/skill` reference in CLAUDE.md, AGENTS.md, `.claude/skills/**`, `docs/hooks.md` resolves (`task --list-all`, filesystem). It would currently flag: bare `cargo test`/`npm test`/`go test` recipes in `audit` and `bugfix` that the task-graph rules forbid; the `/pre-completion` table rows that no longer match `affected-gates.py` gate names; unreferenced `.claude/agents/*`.
8. **Decide storystore and bugshot: wire or silence.** storystore: either land `str-u394l.3` (`stories-init` + the already-written `check_docs_stories` patrol) or set `agent_env_doctor_skip_plugin=storystore`. bugshot: CLI/TUI output *is* rendered output (walkthrough/gauntlet transcripts, `shatter report` HTML/markdown); a `capture-command` that runs `demo/walkthrough.sh --auto --delay 0` into text/ANSI snapshots would make `vizline/vizdiff` a real regression gate for `/walkthrough-review`. Otherwise set `agent_env_doctor_skip_plugin=storystore,bugshot`. Either way stop paying the nudge every session.
9. **Stale-state sweep as a patrol check.** Extend `drift-patrol.py` with `worktree-hygiene`: registered worktrees whose branch is merged into origin/main, prunable worktrees, `/tmp/land-work-preview-*` older than 1 day, directories under `~/.local/share/worktrees/shatter/` that are not git repos, branches without worktrees and no in_progress bead. Emit `bento:closure` as the remediation.
10. **Retire hook-bypass instructions.** Memory says the corrupting git test is fixed; drop the `--no-verify`/`core.hooksPath=/dev/null` guidance from memory and AGENTS.md, set `BEADS_HOOK_TIMEOUT` sanely in `.beads/config.yaml`/hook template, and add a smoke test that `bd hooks run post-checkout` completes in <10 s in a linked worktree (the 300 s timeout is the root cause of both bypass memories).
11. **Populate `.codex/` or delete it.** Empty `.codex/` and `.agents/` dirs plus an AGENTS.md written for Claude tool names (`Grep`, `Read`, `TeamCreate`, `Monitor`) means Codex sessions get instructions they cannot follow. Either add Codex-specific notes (no require-worktree hook exists there) or remove the dirs and mark Claude-only sections.

### bento (`~/project/bento`)

13. **agent-env-doctor: add repo-state checks.** Detect `core.bare=true` in a non-bare checkout, prunable worktrees, `/tmp/land-work-preview-*` leftovers, and dead worktree dirs under the configured worktree root; today it only checks imports, hook binaries, dormant plugins and `.agent-mode.local`. These are exactly the states this repo is in.
14. **agent-env-doctor: dormancy nudge needs a decision path, not repetition.** Nudges print every session with no snooze and no "decided: not applicable" state. Add a one-shot prompt on first sighting that offers "wire now / skip plugin / remind in N days", writing the answer to `.agent-mode.local`. Also collapse the nudge to one line after the first session.
15. **land-work: always clean previews and record verifier runs.** Five `/tmp/land-work-preview-*` worktrees are left in shatter despite the skill's rule. Make `land-work-create-preview.py` register an atexit/`trap` cleanup and have `land-work-run-verifier.py` refuse to start if previews from earlier runs exist (or prune them). Capture verifier stdout/stderr to `<preview>/verifier.log` and report "killed before output" distinctly from "failed", closing the first-run-flake folklore.
16. **land-work: handle diverged primary checkout natively.** The memory `feedback_primary_checkout_diverged_local_main` describes hand-rolling a merge from the preview worktree when the primary's local `main` is ahead of `origin/main`. Make that the default: merge and push from the preview, then ff-sync the primary; error clearly if the primary is bare or dirty.
17. **land-work/wire-land-verifier: add a "did anything run" assertion.** The verifier contract accepts `selected_checks` but not evidence of execution. Require each check to report wall time and a `executed: true|cached` flag; treat all-cached as failure by default (same intent as the existing "zero selected checks" rule).
18. **launch-work vs superpowers `using-git-worktrees`: publish a precedence note.** Both are "invoke before editing". Bento's docs should state that when superpowers is installed, `launch-work` supersedes `using-git-worktrees`/`finishing-a-development-branch`, and the SessionStart output should say so once (or offer a `superpowers_overlap=off` toggle).
19. **check-unpushed Stop hook: don't trap agents into leaving worktrees.** Combined with "never remove worktrees" prose, agents stop in a worktree that is clean+pushed and never land. Consider printing "branch pushed but not landed — run land-work or closure" as advisory so the landing step is nudged, not just the push.
