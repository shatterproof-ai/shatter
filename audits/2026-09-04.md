# Shatter project audit — 2026-09-04

Scope: full review of code, documentation, design, goal fulfillment, UI, quality
gates, tracker, and the agent system that operates on this repo (project
instructions, bento, bugshot, storystore, global dotfiles guidance, Claude Code
memory). Observation only: nothing in the repo was changed except removing a
rapid failfile my own test run created (preserved in the audit evidence).

Method: nine parallel read-only reviewer agents (Rust quality, frontends and
protocol, docs accuracy, docs quality, design and foundation, tracker hygiene,
agent system, session retrospective, usability) plus direct gate runs. Detailed
per-area reports are in `audits/2026-09-04/` next to this file.

---

## 1. Executive summary

**Overall health: YELLOW.** The product works end to end for TypeScript and Go
and the engine is real, but the project's *verification story* is not
trustworthy on this machine, and the agent workflow that produced the last two
months of work has left broken state behind that nothing detects.

Headline findings, in priority order:

1. **Gates can pass without executing anything.** `task check` returned
   "up to date" for every stage in 0.5 s; `--force` does not propagate into
   `check-governed`'s nested stages (the Taskfile admits this); the only way to
   force a real run is deleting `.task/checksum` or forcing each leaf. The
   land-work verifier, `/pre-completion`, and every "gate passed" claim in
   recent landings share this weakness. When I forced the leaves: Go has a
   genuine failing property test, and core fails three tests because of the
   next item.
2. **The primary checkout is broken.** `.git/config` has `core.bare = true`
   (set 2026-09-03 08:31, traced by the retrospective to a recovery session on
   2026-08-23). `git status` fails there, Go's VCS stamping fails, and three
   core `scm` tests fail. Every landing instruction that touches the primary
   checkout is currently impossible, and no doctor notices.
3. **Documentation contradicts current behavior at the first touch.** The
   QUICKSTART's first command is refused by the default-deny host-write policy
   (landed 2026-07-09, absent from SPEC.md and the changelog). One SPEC config
   example cannot deserialize. The docs gate that would catch prose drift
   (`str-wurp`) has been open since July, and the docs lint gate silently
   skips because none of its tools are installed.
4. **Protocol gates have silent no-ops.** The registry validator's TS source
   extraction matches nothing and still prints "All checks passed"; message
   shapes are hand-mirrored in four places with only enums generated; seven
   files cite divergence IDs that no longer exist and assert a false claim.
5. **The two exploration engines have drifted.** The concolic orchestrator
   hard-codes side-effect capture, has its own `ExploreConfig` with 11 of 28
   fields shared, and duplicates the shrink pass verbatim. This is the exact
   hazard CLAUDE.md warns about, present in the code today.
6. **Tracker and git state are stale.** `bd` was down for the whole audit (an
   orphaned dolt server holds the lock); 13 of 14 in-progress issues are dead
   claims 54 to 93 days old; six finished branches sit unmerged with open,
   unclaimed issues; local main is ahead of origin; five land-work preview
   worktrees are orphaned. The July audit's report was never committed.

- **P2 Verifier claims CI parity but is not CI.** `land_work_verifier.sh` says
  it runs "the same gates ci.yml uses" but runs `test-standard + parity +
  conformance`; CI runs `task check`. Three different definitions of
  "verified" exist (`check`, `affected`, verifier).

## 4. Code quality (Phase 2)

Rust workspace: ~212k lines of source, 87 of 97 core files over 500 lines, 20
files over 2,000. Frontends: TS 16.7k non-test, Go 30k, Rust frontend 30k
(with `executor.rs` alone at 16,125 lines / 594 KB).

Strengths: module docs and `///` coverage are high by discipline; `thiserror`
enums are used consistently in core; TODO/FIXME count is near zero (tracker IDs
are used instead); TS has zero `any` in production and strict tsconfig; Go
has golangci v2; proptest/fast-check/rapid coverage is real where it exists.

Findings:

- **P1 Parallel-path drift, confirmed.** `explorer::ExploreConfig` (28 fields)
  and `orchestrator::ExploreConfig` (19 fields) share 11 and are hand-translated
  at `shatter-cli/src/commands/explore.rs:5138-5171`. The orchestrator has no
  `capture_side_effects` field and hard-codes `capture: true|false` at eight
  `Command::Execute` sites, so `--capture-side-effects` cannot affect concolic
  runs. The shrink pass is a verbatim 36-line copy (`explorer.rs:1705-1760`
  vs `orchestrator.rs:3434-3490`); 26 identical 8-line windows exist between
  the files.
- **P1 Giant functions.** `run_explore` 2,658 lines at brace depth 15
  (`commands/explore.rs:4116`); `run_scan` 1,393; `parallel_scan_with_progress`
  1,346 (undocumented); `explore_with_oracle` 1,307; `main` 1,234. Eight
  non-test functions exceed 500 lines.
- **P1 Rust frontend `executor.rs`** mixes harness codegen for three modes,
  caches, axum adapter codegen, and an 8,500-line inline test module.
- **P2 Conventions claimed but not enforced.** rust-conventions names
  `clippy::unwrap_used`/`missing_docs` as "the enforcement path"; nothing sets
  them. ts-conventions lists ESLint rules; shatter-ts has no ESLint. Go's
  golangci excludes `encoding/json.Unmarshal` from errcheck, which is how
  malformed protocol input becomes a zero-value struct that "succeeds".
  30 `#[allow(clippy::too_many_arguments)]` suppressions signal overdue
  parameter structs.
- **P2 shatter-cli ignores its own error convention.** Zero `anyhow`, 56
  `Result<_, String>` signatures, and `main.rs:1381 categorize_error`
  classifies exit codes by substring-matching `Display` output.
- **P2 Risky panics.** `scan_orchestrator.rs:2270`
  `rx.recv().await.expect("pool should not be empty")` panics when all
  senders drop (a reachable error path); `:2244/:2254` `try_send().expect`.
  19 `Mutex::lock().unwrap()` sites in the Rust frontend can permanently kill
  a long-lived stdio session on a single poisoned lock.
- **P2 Property-test gaps.** 43 of 97 core modules have no `proptest!`,
  including `frontend.rs` (protocol boundary), `invariants.rs`,
  `string_mutation.rs`/`array_mutation.rs`, `behavior.rs`, `call_graph.rs`.
  Go packages `launcher`, `sandbox`, `config`, `reconstruct` have no rapid
  tests.
- **P3** `shatter-core` dev-depends on `shatter-llm`, which depends on core
  (cycle); 41 `writeln!(..).unwrap()` in CLI markdown builders; `anyhow` in
  core used by one file; magic literals in CLI wiring (`plateau_threshold: if
  mcdc { 60 } else { 20 }`).

Full detail: `audits/2026-09-04/rust-quality.md`, `frontends-protocol.md`.

## 5. Protocol consistency (Phase 3)

- Wire naming is uniformly snake_case; handshake capability lists in all three
  frontends match `parity-matrix.yaml` exactly; enum codegen `--check` passes.
- **P1 `validate-protocol-registry.py` source-parity layer is a no-op for TS**
  (`extract_ts` regexes `type Command = …` in a file that now only re-exports
  generated enums; all sets come back empty; script prints "All checks
  passed") **and false-warns for Rust** (reads `protocol.rs` while the
  literals live in `handler.rs`). GOVERNANCE.md presents it as a required gate.
- **P2 Only enums are generated.** Message shapes are hand-mirrored in core,
  TS, Go, Rust FE. Result: TS `Request`/`Response` unions lack `plan`,
  `get_invocation_plan`, `invocation_plan`; Rust FE emits undeclared
  `is_async` and `harness_mode`; Go lacks `connection_failures` and
  `runtime_crypto_boundaries`. `registry.yaml` `field_model` is never checked
  against source.
- **P2 SymExpr builders drift.** TS has three builders (not two) with different
  unknown-collapse rules and a property-chain path that ignores the flow map.
  Go has dual paths in two packages over a duplicated `symExpr` type, drifting
  on true/false/nil, string unquoting, nested selectors, `omitempty`. Rust's
  instrumentor hand-formats JSON and supports only comparison/logical ops, so
  runtime constraints are narrower than the static conditions the same
  frontend reported. Cross-frontend: Go emits calls as
  `{name:"recv.Method", receiver:null}`; TS/Rust emit
  `{name:"Method", receiver:<expr>}`. Untracked.
- **P2 Stale contracts.** Seven files cite the deleted divergence
  `error-code-preflight-failed-typescript-only` and claim Go/Rust do not emit
  `preflight_failed` (both do: `handler.go:394`, `handler.rs:650`). Two more
  dangling IDs in crate CLAUDE.md. `frontend-parity/SKILL.md` contradicts the
  matrix on Go side effects, Go `ite`, Rust analyze/execute status. The one
  `resolved` matrix entry expires 2026-09-11 and will turn `task parity` red
  on an unrelated branch.
- **P3** Discriminator key is `kind` for some core types and `type` for
  others; `ErrorCategory` vocabulary differs between TS and the registry.

## 8. Foundation and design (Phase 6, questions 4 and 5)

| Component | Status | Notes |
|---|---|---|
| Explorer loop | Solid | Not random: strategy scheduler with Z3 as a reactive strategy |
| Concolic orchestrator | Solid, heavy | Worklist, prefix negation, MC/DC, unrolling, fuzz fallback, six termination reasons |
| Z3 solver | Partial by design | Int/Real/Bool/Str; arrays/objects default to Int silently; no bitwise; floats as rationals |
| Behavior maps / clustering | Solid | Path-keyed classes, canonical example, dependency traces feed mocks |
| Invariant detection | Partial | Nine Daikon-style kinds; confidence hard-coded 1.0; no min-sample guard |
| Test generation | Partial | Jest/Vitest/Go only; no Rust emitter; runnability untested |
| Input generation | Solid, god module | 9k lines mixing input mutation and mock-value generation |
| Protocol/frontend boundary | Solid, leaky edges | One long-lived NDJSON child per session; 42 `Language::Rust` match sites in 9 core/CLI files |
| Execution adapters | Partial, accreting | ≥3 substrates per language plus sandbox switch; React shim is "migration material" |

Design findings:

- **P1 Two exploration engines behind a `concolic: bool`** threaded through
  seven sites in `main.rs`, with duplicated termination, plateau, budget, and
  progress code. Unification path: express orchestrator phases as
  `InputStrategy` impls, make `--concolic` a weight preset, collapse
  `TerminationReason`/`StopReason`.
- **P1 Four intra-crate cycles** (`explorer↔orchestrator`,
  `explorer↔scan_orchestrator`, `orchestrator↔strategy`,
  `input_gen↔orchestrator`); a leaf config type depends on the top-level scan
  scheduler. `lib.rs` is a flat list of 96 `pub mod` with no layering.
- **P1 Config surface.** 24 subcommands, ~600 flag instances (explore 79, scan
  69), `args.rs` 4.1k lines already boxing variants to stay under clap's stack
  budget; four config channels (flags, `--set`, two files with disjoint
  schemas, ~25 `SHATTER_*` env vars only partly in the precedence table).
- **P2** Hand-wired language dispatch (adding a fourth language touches 15+
  files; three different distribution mechanisms for three frontends);
  `IsolationMode::None` default with a 1,765-line nondeterminism module
  treating the symptom; Z3 called synchronously inside the async loop.
- **P2 Accreted subsystems.** `shatter-vs` (v1 fuzzer plus extension shell,
  5 months stale, in no gate or doc), `shatter-report/`, `cross/` are dead;
  `benchmarks/` is half-built. `shatter-llm`, `perf/`, `shatter-rust-runtime`
  are live.

Full detail: `audits/2026-09-04/design-foundation.md`.

## 9. Usability and UI (Phase 8, question 6)

Sources: captured and live runs of `target/release/shatter 0.1.0`
(`audits/2026-09-04/ui/`), help text for all 24 subcommands, the walkthrough
and gauntlet logs, `shatter-vs`, and the HTML report code.

What is good: the markdown explore report is scannable in ten lines (one
heading per function, a call/outcome table, coverage summary); no ANSI leaks
when piped and `NO_COLOR` is honored; the spec markdown reads well; the spec
JSON and `spec-diff --json` are well shaped; the host-write refusal message is
a model error message (it lists the two remedies with exact commands).

Findings:

- **P1 `--spec-json` on stdout is unparseable.** `shatter explore --spec-json`
  writes the markdown explore report and then the JSON spec on the same
  stdout; `json.load` fails at line 1. Only `--spec-out FILE` or `-o` produce
  clean JSON. QUICKSTART recommends the pair but never warns.
- **P1 Exit codes contradict SPEC §2.11.** Missing file, unsupported
  extension, unknown function, malformed spec file, and the sandbox refusal
  all exit 1; SPEC reserves 2 for tool and usage errors and gives the
  malformed-spec case as its example. Only clap usage errors exit 2, so a CI
  job cannot tell "regression found" from "spec file corrupt".
- **P1 First run is refused** without `--allow-host-writes` (§6); QUICKSTART
  §2's first command is exactly the refused one.
- **P1 `scan` and `run` disagree on a missing Rust frontend.** `scan` warns,
  skips `.rs`, exits 0 and prints the 600-character remediation twice; `run`
  aborts with exit 1 and no report.
- **P1 Demo gates test exit status, not sanity.** Walkthrough: Rust
  `classify_number` and `safe_divide` report 0% coverage with every call
  throwing `input 0 deserialization failed: … expected a string`, marked
  `(ok)`. Root cause is an analyzer/harness type disagreement in the Rust
  frontend (params typed numeric by the analyzer, deserialized as `String` by
  the generated harness, `shatter-rust/src/executor.rs:2471-2498`). The
  walkthrough's error regex looks for `failed to deserialize`, which does not
  match `deserialization failed`. Gauntlet: 390 `Teardown scope mismatch`
  errors across three scan steps because exported `setup`/`teardown`
  lifecycle helpers in `setup-file-level.ts` are discovered and fuzzed as
  targets; `gauntlet_check_output.py` cannot flag thrown-error clusters and
  the function reaches 100% coverage so no FAIL row fires. Both gates say
  "All steps passed".
- **P1 Every leaf subcommand shows 13+ flags.** The global timing flags,
  `--allow-host-writes`, `--set`, `--color`, `--render`, `--project-dir` are
  repeated on `init`, `cache`, `telemetry`, `spec-diff`, `doctor`; `spec-diff
  --help` is 60 lines with two flags of its own. `explore` has 79 flags with
  globals shuffled into command flags by declaration order and no
  `help_heading` grouping.
- **P2 Flag vocabulary drift.** Five spellings for a per-function timeout
  (`--per-function-timeout`, `--timeout-explore`, `--timeout-per-fn`,
  `--timeout`), three for a whole-run cap, five for machine-readable output
  (`--json`, `--spec-json`, `--format json`, `--output-format`, `--yaml`),
  four for output path, four for project dir.
- **P2 Terminology drift.** explore says "path(s)", spec says "Class N",
  scan says "Cluster N", JSON uses `classes`/`equivalence_classes`/`behaviors`,
  help says "equivalence classes, behavior map". Four names for one concept in
  one session.
- **P2 `spec-diff` reports renumbered classes as ADDED and REMOVED pairs.**
  It matches classes on the exact `BranchPath` (`spec_diff.rs`, `old_by_path`),
  so when a new branch shifts branch IDs, unchanged behaviors no longer pair;
  one real change reports 3 added / 2 removed. The index-bearing `label`
  ("Class 3 — …") compounds the noise but is not the matching key.
- **P2 Spec preconditions are single-sample tautologies** (`param[0] == 2`
  for the positive-even class) encoded as externally tagged enums
  (`{"AllEqual": {...}}`); the symbolic constraints already in core are not
  exported.
- **P2 Implicit init on a bare `explore`** writes `.shatter/`, `config.yaml`,
  and a `.gitignore` into the cwd and prints "Created …" lines into stdout
  ahead of the markdown, with "detected language: unknown" for a `.ts`
  target.
- **P2 `scan` prints two consecutive reports** (`# Scan Results` table then
  `# Shatter Scan Report`), uses absolute paths with `::` where explore uses
  relative `file:function`, and renders "0 uncovered branch(es) (58.3%
