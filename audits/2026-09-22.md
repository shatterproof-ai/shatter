# Shatter project audit — 2026-09-22

Scope: full review of code, documentation, design, goal fulfillment, UI (CLI
output and generated artifacts), quality gates, tracker, and the agent system
that operates on this repo, including the first-party pieces that shape agent
behaviour from outside it (bento, bugshot, storystore, shatter-agents, global
dotfiles guidance, Claude Code memory). Audited SHA: `16794cef` (== origin/main
at start).

Method: parallel read-only reviewer agents per area (gates, core engine, CLI UX,
artifacts, TS/Go/Rust frontends, protocol and parity, tests and CI, docs, goals,
agent repo, session retrospective, bento, plugins and guidance, prior-audit
regression). Every finding was then checked by an independent verifier, which
could confirm it, confirm it in part, or correct its priority, and was
deduplicated against the shatter, bento, bugshot, storystore, shatter-agents and
dotfiles trackers. Priorities below are the **verified** priorities. Evidence
lives next to this file in `audits/2026-09-22/` (`areas/*.md`, `gates/*.log`,
`cli-ux-transcripts/`, `artifact-samples/`, `goals-runs/`, `sessions/`).

Caveat on timing: the host ran at load average 60–210 on 32 cores for the whole
audit, largely because of the audit's own parallel agents. Treat every wall
time as an upper bound. Findings about timeouts carry medium confidence unless
stated. Coverage and correctness findings do not depend on timing.

Finding IDs (`gates-01`, `core-03`, …) refer to the per-area evidence files.
In several areas the ID number differs from the area file's heading number;
see the crosswalk appendix at the end.
Tracker IDs (`str-…`, `bento-…`, `sa-…`, `bgs-…`, `ss-…`, `dotfiles#…`) refer to
existing issues. **NEW** marks a finding with no existing issue.

## 1. Executive summary

**Overall health: RED.** The product still works for plain pure functions in
all three languages. The Rust demo now executes, where the prior audit found it
at 0% coverage. But the project cannot currently tell whether it works, and
several user-visible outputs are wrong in ways that no gate detects:

1. **CI has run no product test suite since about 2026-08-30.** The `meta` stage
   of `task check` runs a test that calls `task --list-all --json`. On go-task
   3.50 and 3.53, that JSON listing writes checksum files for all 39 tasks that
   declare `sources:`. Stages 2 and 3 then report "is up to date" and are
   skipped: core, cli, ts, go, rust-fe and rust-rt tests, E2E, conformance and
   parity. Two independent reviewers reproduced this. It is the root cause of
   the open P1 `str-qwua7.3`, and it has made CI and local `task check` hollow
   for three weeks (gates-01/02, tests-ci-01).
2. **When the gates were forced to run, main was red.** Results: a Go config
   test fails (it walks up to a stray `/tmp/.shatter/config.yaml`). The core
   benchmark times out, and fail-fast then leaves 87 tests unrun. TS handler
   tests time out under load (they pass on rerun).
3. **Wrong answers.** Several new P1 correctness bugs, found through behavioural
   probes that the prior audit did not run:
   - The Z3 translation splits one numeric parameter into separate Int and Real
     variables, so the solver returns x = 1.5 for 0.5 < x < 1 (core-01).
   - The random explorer's float probe discovers paths but never counts them,
     so reports say "0 path(s)" while the progress line says 2 or 3 (core-02
     and five duplicates).
   - `--setup` is silently ignored under `--concolic`, although the issue that
     claimed to fix it is closed (core-03).
   - Explore silently resumes earlier results even after `--concolic` or the
     budgets change, and labels them with the new mode (artifacts-01 and five
     duplicates).
   - `revalidate` ignores return values and exits 0 after a real regression
     (goals-02).
   - `shatter diff` has no producer: nothing writes a snapshot (goals-01).
   - `explore -o out.json` writes an empty `no_targets` bundle after a
     successful run (cli-ux-01, artifacts-02).
   - TS switch, ternary and value-position `&&`/`||` branches are analyzed but
     never instrumented, and the analyze and instrument branch IDs desync
     (frontend-ts-02).
   - TS runtime path constraints can contradict the concrete run, because the
     instrumentor uses one end-of-function flow map for every branch
     (frontend-ts-01).
   - The Go frontend types rune literals as strings (frontend-go-03). An
     installed Go frontend cannot run any uncached target (frontend-go-01).
   - Rust crate-bridge fails any function that prints (frontend-rust-01).
   - `SHATTER_SANDBOX_BACKEND=docker`, the documented remedy, turns off write
     protection for TS and Rust targets (docs-01).
4. **Distribution is broken.** Build and Release has succeeded 0 times in 200
   runs, and no GitHub release exists, so `install.sh` and `action.yml` cannot
   install anything. The documented `go get -tool` path does not resolve. The
   shatter-agents plugin ships a `shatter-diff` skill for a command that does
   not exist, and its pre-commit example blocks every commit.
5. **The agent system lets defects in and keeps them.**
   - Issues close when code or docs merge, not when the symptom is gone. About
     25 closed-but-unfixed items were found (§11, §12).
   - The scheduled Drift Patrol workflow has never run (it points at a
     nonexistent `go.mod`).
   - AGENTS.md mandates `bd sync`, which no longer exists, and the tracked JSONL
     has been frozen since 09-07.
   - Every commit since June carries the test-fixture identity `Test
     <test@example.com>`.
   - Memory still tells agents to use `--no-verify`, and the bento guard is
     bypassed by `/usr/bin/git`.
   - The global guidance that would have caught much of this is loaded in
     almost no session.
6. **Follow-through on the 2026-09-04 audit.** bento and dotfiles closed every
   item within days. Shatter closed 12 of its 62 `str-qwua7` children, all
   small, and none of the structural P1s. The report itself was never pushed,
   and 62 issues cite files that exist only on that local branch.

- **core-08** (P2) About 5,100 production-dead lines: `recursive.rs`, `array_mutation.rs`, `reporter.rs`+`clustering.rs`, sequential `scan()`, `shrink_witness`, `mutate_mock_values`. The prior audit graded clustering "Solid". → Delete them or wire them behind an issue, and add a module-reachability check to `task check`. *Partially str-qwua7.59 (export.rs only). NEW for the rest.*
- **core-10** (P2) str-qwua7.49's premise is wrong. The `expect` sites it names are unreachable. The real failure is that an empty worker pool reports every queued task as a task timeout. → Retitle and rescope .49 around `ScanError::WorkerPoolExhausted`. *Update str-qwua7.49.*

### 4.3 TypeScript frontend

- **frontend-ts-01** (P1) The instrumentor's data-flow map ignores program point. One end-of-function map is used for every branch, reassignment from an unresolvable call keeps the stale binding, and loops are not widened. Recorded constraints contradict the concrete run: `stale(5,0)` records `b > 0` as taken. → Snapshot the flow map at each branch, and treat reassignments from unresolvable calls and loop-carried variables as unknown. Add an oracle test: evaluating the constraint on the concrete inputs must give `taken`. Downgrade inconsistent constraints in core via `triage::evaluate_constraint`. *NEW.*
- **frontend-ts-04** (P2) A shadowed callback parameter resolves to the outer parameter. → Resolve through TypeChecker symbols. *NEW.*
- **frontend-ts-05** (P2) Target errors whose message contains "timeout" are classified `timed_out`/infrastructure. → Classify only harness-owned timeouts as timeouts. *NEW.*
- **frontend-ts-06** (P3) The async `Promise.race` timer is never cleared, and jest `forceExit` hides it. *NEW.*
- **frontend-ts-07** (P2) `parseRequest` validates only the envelope, so a bare `execute` crashes as `internal_error`. `validCommands` is hand-maintained. → Add per-command validators generated from `field_model`, and derive dispatch from `ALL_COMMANDS`. *NEW.*
- **frontend-ts-10** (P2) The protocol round-trip tests are `JSON.parse(JSON.stringify(x))`. No TS test touches `protocol/schemas` or `fixtures`, although the Taskfile declares them as sources. → Validate responses with ajv and drive the fixtures through `parseRequest`. *NEW.*
- **frontend-ts-11** (P2) The builder-parity property only generates node kinds both builders already handle and compares only unknown vs non-unknown. The analyzer builder is untested. → Use a fixed corpus and assert output equality. *str-jalv/str-hicn closed-but-unfixed; str-rf2v.*
- **frontend-ts-12** (P2) There is still no ESLint. typescript-eslint finds 72 production issues, including dead code and a default export. *str-qwua7.31.*
- **frontend-ts-14** (P3) `??`, `**`, shifts, element access, `as`/`!` and template literals collapse to unknown. *NEW (09-04 A5, never filed).*
- **frontend-ts-17** (P3) On stdin EOF or shutdown the frontend exits without draining in-flight requests, and `'protocol 0.1.0'` is hard-coded. *NEW.*

## Coverage gaps (completeness review)

What the user asked for that this audit did not examine, or examined thinly:

- **Visual UI review.** The HTML reports were read as text. No one rendered
  them in a browser, screenshotted them or ran bugshot on them, so the claims
  about "coherent HTML styling" and the HTML tiles (artifacts-13/15) are not
  based on the rendered page. Terminal output was checked for ANSI leakage but
  not viewed at different widths or colour settings.
- **Security.** There was no dedicated security review. Only incidental items
  exist: the sandbox bypass (docs-01), the Jev key in `Debug` (frontend-rust-16),
  and control bytes in reports (goals-17). Not examined: `install.sh` and
  `action.yml` trust model (curl-to-shell, checksum verification), the
  generated harness code's exposure to target code, and what telemetry sends
  (it is on by default; cli-ux-18 checked only the subcommand list).
- **Dependency health.** No `cargo audit`/`cargo deny`, `npm audit` or
  `govulncheck` run, and no check of outdated or duplicate dependencies beyond
  js-yaml v3 (frontend-ts-16).
- **Engine efficiency.** Explore/scan throughput, memory use and parallel
  scaling were not measured. The host load (60–210) made every timing
  unreliable, so "efficient" in the request is covered only by gate-time
  findings (gates-11, frontend-rust-06/12, sessions-04).
- **Gate tiers not run:** `task affected`, `task test-quick`,
  `task test-standard`, and `cargo fmt --check` (tree known not
  rustfmt-clean; sessions-11). `task check` was run but was hollow (gates-01),
  so after gates-01 is fixed the full check must be re-run before any "main is
  green" claim is made.
- **docs/stories.** Confirmed absent (docs-11). The storystore skills
  (`stories-coverage`, `stories-audit`) were not run, because the inventory
  finds 0 CLI surfaces (plugins-05); the proposed seed story list is the
  auditor's, not the maintainer's.
- **First-party repos not examined:** `~/project/refute` (installed as a
  plugin, so it shapes agent behaviour), `examples` (the unpinned test-input
  repo, tests-ci-09; its own quality and known-answer comments were used but
  not reviewed), `sandbar`, `forenz`, `flotsam`, `dev-setup`, `jev-trials`.
  `holdout` and `shatter-effectiveness` were looked at only for goals-10.
- **Codex side of the agent system.** The global instructions were reviewed
  from the Claude Code side (loading, memory, hooks). Codex-specific config,
  skills and session behaviour were not examined, and neither was whether
  bento's cross-check skill works in the Codex direction.
- **Global Claude Code settings and hooks.** `~/.claude/settings.json`
  permissions and hooks were inspected only as far as `$DOTFILES`
  (sessions-14) and plugin `autoUpdate` (plugins-04).
- **Readiness review of drafts.** No draft had a fresh-reviewer
  `issue-readiness-check` (see §15).
- **Finding traceability.** See the crosswalk appendix: gates findings have no
  area write-up, and several areas' IDs do not match their headings.
